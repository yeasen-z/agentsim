# Agent Sim

Agent Sim is a Python framework for building deterministic, inspectable
environments for developing and evaluating tool-using agents.

Its core design rule is simple:

> Python maintains ground truth; language models add semantic realism.

State transitions, tool effects, safety constraints, and success checks remain
deterministic. Natural-language instructions and feedback can be generated by
an LLM without allowing it to decide whether a task succeeded.

> Status: Agent Sim is an early-stage framework. The core APIs are usable, but
> they may change before a stable 1.0 release.

## Features

- Hidden Python state with serializable entities and metadata
- Deterministic tool registration and execution
- Rule-based task verification and forbidden-tool checks
- Complete per-step trace recording
- Pluggable scenario registry and environment adapters
- LLM simulation interfaces with no required provider SDK
- Multi-agent roles and orchestration primitives
- Built-in scenarios for contacts, SMS, calendar, settings, gallery,
  browser, clipboard, and email workflows

## Requirements

- Python 3.9 or newer

## Installation

Install the package from a local checkout:

```bash
git clone https://github.com/yeasen-z/agent-sim.git
cd agent-sim
python -m pip install .
```

For development, use an editable install with the development tools:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

On Windows, activate the environment with `.venv\\Scripts\\activate`.

## Use as a dependency

Keep application code in a separate project and install Agent Sim into that
project's virtual environment:

```text
research/
├── agent-sim/
└── my-agent-project/
    ├── .venv/
    └── main.py
```

```bash
cd my-agent-project
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ../agent-sim
```

Application code can then import the installed package normally:

```python
import agent_sim
from agent_sim import OperationEmulator

print(agent_sim.__version__)
```

Do not modify `sys.path` to import the package. An editable install makes local
framework changes immediately available to the application.

## Core model

An environment is assembled from five pieces:

1. `ScenarioDefinition` describes the environment and its tasks.
2. `HiddenState` stores authoritative state.
3. `ToolExecutor` applies deterministic operations to that state.
4. `Verifier` checks explicit success conditions and safety violations.
5. `OperationEmulator` coordinates observations, actions, verification, and
   tracing.

The primary interaction loop is:

```python
observation = emulator.reset(task, seed=42, instruction="Complete the task")
tools = emulator.available_tools()
result = emulator.call_tool("tool_name", {"argument": "value"})
verification = emulator.verify()
trace = emulator.get_trace()
```

`OperationEmulator` is configured with a scenario, state initializer, tool
executor, verifier, and optional observation compiler. Built-in scenario
implementations are available from `agent_sim.scenarios`; see [`examples/`](examples/)
for runtime integration examples.

## Public modules

- `agent_sim.core`: state, tools, tasks, verification, tracing, registry, and
  environment interfaces
- `agent_sim.scenarios`: built-in contacts, SMS, calendar, settings, gallery,
  browser, clipboard, and email simulation environments
- `agent_sim.agents`: LLM client adapters and agent helpers
- `agent_sim.llm_sim`: instruction, content, feedback, and user simulators
- `agent_sim.multi_agent`: roles, agents, messages, and orchestration
- `agent_sim.OperationEmulator`: the main environment coordinator

## Project scope

Agent Sim provides simulation infrastructure rather than a GUI emulator, a
hosted service, or a benchmark dataset. The scenarios under
`agent_sim.scenarios` are installed with the package and can be imported by
downstream projects.
